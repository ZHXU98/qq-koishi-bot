# HTML 复盘报告输出规范

分析/复盘型回答产出 HTML 文件时遵循本规范。

> **权威原则**：图表库、JS 自检、图/表切换、双轴与空值细则以官方 `wb-finance-skill/references/html-report-style.md` 为准。本文件只补充 A 股复盘的**章节结构**与**配色约定**；路径一～四按结构写 HTML，路径五用 `hotspot_report_template.html`。

## 排版自由度（优先读这一条）

本文件给的是**风格方向与内容要素**，不是模板。每次生成报告时，版式由模型按当期内容自行设计：

- 允许自由决定：章节顺序、分栏方式、卡片/表格/图的组合、标题句式、字号层级、留白节奏
- 允许每期长得不一样，同一份报告内部不同章节也可以采用不同呈现方式
- 唯一要求是「读起来像一份专业研报」：结论先行、层次清楚、数字对齐、留白克制
- 禁止照抄某一份历史 HTML 的 class 结构和骨架；也禁止把本文件的章节清单当成必须逐条出现的小标题
- 图表按「这一节讲什么」选型（趋势折线 / 对比条形 / 分布柱 / 占比环 / 表格），不要为了凑图表而画图

参照而非套用：可以借鉴刊头、结论卡、指标带、双列强弱、编号清单这些**表达手法**，但每期应重新组织。

## 必须守住的硬约束

只有三条：

1. **浅底深字**，禁止暗色仪表盘当整页背景
2. **颜色语义**：上涨红（`#dc2626` 一类）、下跌绿（`#16a34a` 一类），不得反向
3. **首屏有结论**：第一屏必须能读到"今天怎么定性"，形式任意（结论卡 / 导语段 / 提要条 / 大字标题均可），不强制某个 class 名

除此之外没有格式禁令。

## JS 语法自检（交付前必须执行）

见 wb-finance `html-report-style.md` §0。含 ECharts 的报告交付前必须 `node --check`。

## ECharts 图表库引用

引库与 option 骨架可直接套用 wb-finance 文档；data / 标签 / 配色按当期设计。

```html
<script src="https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js"></script>
```

若改为 head **内联**整库：业务初始化须与库分属两个平级 `<script>`（或库在 head、初始化在 body 末尾**单个** script）。**禁止** `<script>` 嵌套；内层 `</script>` 会截断外层，导致 `echarts.init` 不执行。

本地离线渲染时，可把 echarts 下载到项目 `vendor/` 并用相对路径引用。

## 配色方向

**本 skill 视觉倾向**：石板蓝/行情蓝作点缀色（`#4a5b78`～`#1e3a5f` 区间），米白或纯白作底色，用细分割线与灰阶做层次；强调色克制，不要整页铺色块。路径五热点速览仍走橙红脉冲（`#c2410c`）。

## 内容要素（该讲什么，不是该排成什么样）

不同时段的报告，内容要素如下，**顺序与呈现方式自定**：

| 时段 | 必须讲到的要素 |
|---|---|
| 盘前 / 早盘 | 上一交易日结构与关键位 → 隔夜外盘（美股、日韩、商品、汇率）→ 昨日结论逐条检验 → 映射矩阵 → 今日开盘关注与失效条件 |
| 开盘 | 开盘价 vs 昨收的定价程度 → 昨日结构在今日的反转/延续 → 与外盘一致或背离的地方 → 开盘后需要验证的信号 |
| 午盘 | 半日指数与成交额 → 情绪速览（三行）→ 行业强弱 → 午后观察点 |
| 盘后复盘 | 一句话定性 → 量能与涨跌分布 → 指数全表 → 情绪与周期定位 → 技术面（均线/关键位）→ 板块与资金 → 次日关注清单 → 风险提示 |

要素可以合并、可以拆开、可以换名字，但不能缺——缺了就是分析不完整。

## 图表质量要求

趋势/对比/占比用 ECharts；查阅型用表格；优先图/表可切换。细则见 wb-finance §3–§4。
