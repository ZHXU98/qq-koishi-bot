# qq-reply —— 指令中心（被@回复 + 指令）

官方 QQ 机器人通道下的**被动回复容器**：监听群聊 / 私聊消息，识别**被 @** 与**指令前缀**后自动回复。与 `ths-news`（主动定时推送）互补，构成「主动推 + 被动答」的完整机器人。

> 历史上接的是 NapCat（个人号），2026-08-26 起改接 `official-bot-gateway`（官方开放平台）。环境变量名沿用 `NAPCAT_*` 未改，指向的已是网关了。

## 触发规则与权限

| 场景 | 行为 |
|------|------|
| 群聊 · 任意人 @ + **闲聊** | **忽略**（只有特定指令才触发，防止被随便 @ 刷屏） |
| 群聊 · @ + 指令 | 响应；普通成员仅可使用 `groupRestrictedCmds` 内指令，其余回 `restrictedMsg` |
| 群聊 · 不在 `groupWhitelist` 的群 | 完全忽略 |
| 群聊 · 管理员（`admins`）直接发磁链（无需 @） | 自动预览（普通成员无 @ 发磁链仍忽略） |
| 私聊 · 白名单（`privateWhitelist`） | 仅响应指令 / 磁链，闲聊忽略 |
| 私聊 · 非白名单 | 回 `deniedMsg` 拒绝提示（置空则完全忽略） |

> 全部规则通过 `config.json` 调整，**每次收到消息热加载，改完立即生效、无需重启**。

## 架构

```
QQ 用户 ──@ / 指令──▶ 官方 QQ 开放平台 ──▶ official-bot-gateway
                                              │ WS :3101 事件推送
                                              ▼
                                    qq-reply 容器（node:22-alpine，零依赖）
                                              │ 识别 @ / 指令 → 渲染图表
                                              ▼ HTTP :3100（send_group_msg / send_private_msg）
                                        官方网关 ──▶ QQ 回复
```

- **零依赖**：Node ≥ 21 内置全局 `WebSocket`（事件通道）与 `fetch`（HTTP 回复），无需 `npm install`。
- **渲染库**：`@napi-rs/canvas`（主，Canvas 2D，进程级字体缓存 ~50ms）+ `@resvg/resvg-js`（兜底），均从 `ths-news-modules` 卷**只读共享**（渲染 `/ss` `/stock` `/stocks` `/zj` 图表用）。
- **断线自愈**：WS 断开后每 5 秒自动重连。
- **发送重试**：`send_*` 端点 5 次 × 5s，抵御网关间歇超时。
- **配置热加载**：`config.json` 每次收到消息时重新读盘。
- **可写挂载**：仅 `./reply/data`（`/stocks` 组合数据）；`index.js` / `config.json` 仍是只读挂载。

## 快速开始

前置：`official-bot-gateway` 已启动、机器人已登录（`docker logs official-bot-gateway` 看到「✅ 官方机器人已连接 Gateway」）。

```bash
# 1. 生成配置文件（可选，默认值即可直接用）
cp reply/config.json.example reply/config.json

# 1b. 初始化组合数据（/stocks 用；目录不存在时 Docker 会误建成目录，务必先建文件）
mkdir -p reply/data && echo '{}' > reply/data/portfolios.json

# 2. 启动
docker compose up -d qq-reply

# 3. 看日志确认 WS 已连接
docker compose logs -f qq-reply
```

看到 `✅ WebSocket 已连接 ws://official-bot-gateway:3101` 即就绪；然后在群里 @机器人 或在私聊里发 `/help` 验证。

### 离线生产同款图片预览

本机安装渲染依赖后，可以直接导出图片；预览脚本只调用图表的数据获取与渲染函数，把 PNG 写入本地目录，**不会连接 QQ 网关或发送消息**。

```bash
cd reply
npm install
npm run preview:ss

# 图片输出到本机目录（已忽略，不会提交）

```

> 生产容器同样按 `reply/package.json` 安装依赖；容器仅用于部署/迁移，本地预览不依赖容器。

### 🗂️ 股票组合（/stocks）

保存常用组合，之后一条指令出图，适合盯一篮子票。

| 用法 | 权限 | 说明 |
|------|------|------|
| `/stocks -list` | **所有人** | 列出已保存组合（组合名 / 只数 / 更新时间 / 成分股预览 / 出图指令） |
| `/stocks <周期> <组合名 或 股票...>` | **所有人** | 出图。给组合名 → 展开成分股；直接给股票 → 按输入顺序出图 |
| `/stocks -add <股票...> -name <组合名>` | **仅主人** | 新建组合；同名则整组覆盖 |
| `/stocks -update <组合名> <股票...>` | **仅主人** | **整组替换**已存在组合的成分股 |
| `/stocks -del <组合名>` | **仅主人** | 删除组合 |

```bash
/stocks -d 我的持仓                              # 出图（所有人）
/stocks -list                                    # 看有哪些组合（所有人）
/stocks -add 600519 300750 002594 -name 我的持仓   # 新建（主人）
/stocks -update 我的持仓 600519 000858            # 换成这 2 只（主人）
/stocks -del 我的持仓                             # 删除（主人）
```

> **权限分两层**，别混淆：
> 1. **能不能调 `/stocks`** —— 由 `groupRestrictedCmds` 决定（当前已放行 `stocks`），群内所有人可用；私聊另受 `privateWhitelist` 限制。
> 2. **能不能写** —— `-add` / `-update` / `-del` 在 `cmdStocks()` 里用 **`owners` 名单**独立校验，**与 `admins` 无关**。即使某人是 `admins`（甚至能触发全部指令），只要不在 `owners` 里，写操作一样被拒。
>
> **主人识别是双通道**：先比 `owners` 里的 QQ 号，再比网关 `/bindings` 里的 `owner.openid`。
> 之所以要 openid 兜底——官方通道下网关只把**主人**的 openid 反查成 QQ 号下发（`qqByOpenid` 只认 `bindings.owner`），
> 其他人事件里的 `user_id` 是 openid；一旦网关 `bindings.json` 丢失/重置，主人也会退回 openid，只按 QQ 号比对会把主人锁在门外。
> 反过来，给**非主人**放权（`admins`）必须填 TA 的 **openid**，填 QQ 号永远匹配不上。

**`-update` 的边界处理**（写操作可逆性差，宁可拒绝也不猜）：

| 情形 | 行为 |
|---|---|
| 组合不存在 | 拒绝，并给出「改用 `-add` 新建」的现成命令 + 现有组合列表 |
| 只给组合名、不给股票 | **拒绝**。空名单一律不走 `-update`（清空是破坏性操作，必须显式 `-del`） |
| 全部股票解析失败 | **拒绝且原组合保持不变**（防止打错名字把组合清空） |
| 部分股票解析失败 | 用解析成功的替换，并列出跳过的项 |
| 超过 20 只 | 拒绝，**不静默截断**（避免悄悄丢票） |
| 同一只给多次 | 自动去重 |
| 带周期参数（`-d`） | 拒绝并提示：编辑指令不出图，看行情请另发 `/stocks <周期> <组合名>` |
| 一次写多个操作符（`-add` + `-del`） | 拒绝并列出冲突项（不做「后者覆盖前者」的静默处理） |
| `-name` 后无值 | 拒绝（组合名不允许含空格，`-name` 只吃紧跟的一个 token） |
| 组合名含非法字符 / 超 12 字 | 拒绝并给出命名规则（中英文/数字/下划线打头，后接中英文/数字/下划线/点/短横线） |
| 组合名以 `-` 开头 | 该 token 先被识别成未知参数 → 回「未知参数」并附用法 |

回执会显式列出**新增 / 移除 / 当前**三行，换错名单时一眼能看出；`created` 保留、只刷新 `updated`。

> **组合名优先级高于股票名**：参数只有一个且命中已保存组合名时，一律按组合展开（如组合名叫「白酒」，`/stocks -d 白酒` 走组合，不会去搜同名股票）。
>
> ⚠️ **模糊匹配提醒**：股票名走腾讯 `smartbox` 模糊搜索，生僻/无关的中文词可能命中意外标的——实测「持仓」会被匹配成美股 ETF `usGOP.AM`（国会共和党持仓ETF）。写操作回执会列出全部解析结果，保存前请扫一眼；发现不对用 `-update` 改掉即可。

**出图规格**（针对手机截图阅读优化）：

| 项 | 做法 |
|---|---|
| 画布 | 1080px 宽竖版长图，单张 PNG 直出（QQ 对 >1080px 会二次压缩） |
| 列数 | 按数量自适应：1 只 → 1 列；2–8 只 → 2 列；9–12 只 → 3 列；13–16 只 → 4 列（**每行最多 4 个**） |
| 子图 | 精简版走势，**无成交量 / 均线 / BOLL**；K 线为蜡烛，分时为价格线 + 黄色均价线 |
| 纵轴 | **各自价格轴**（自适应各自价格区间），配一条灰色虚线做基准：K 线 = 区间起点收盘价，分时 = 昨收 |
| 配色 | 涨红跌绿（`#e0483e` / `#12a05c`），与 `/stock` 一致 |
| 顶部汇总栏 | 组合名 + 周期/时间（左）；平均涨跌幅 + `N 只 · M 涨 K 跌`（右） |
| 每格信息 | 名称 + 涨跌幅（大字号）；底部 `代码 · 现价` + `区间涨跌幅`（分时为 `振幅`） |
| 窄格降级 | 3 列去掉「现价」只留代码；4 列再去掉「区间 / 振幅」前缀（按实测字宽自动决策，避免重叠） |
| 容错 | 单只取数失败 → 该格显示灰底「取数失败」，**其余正常出图**；图下文字标注失败标的，并另发一条提示 |
| 截断 | 超过 16 只只取前 16 只，并另发一条提示说明 |

| `NAPCAT_TOKEN` | 空 | access token（若启用） |

| `NEWS_QUERY_LIMIT` | `10` | `/快讯` 返回条数 |

| `DAILY_PUSH_HOUR` / `DAILY_PUSH_MIN` | `21` / `30` | 汇总推送时间 |

### config.json（挂载 `/app/config.json`）

| 字段 | 默认 | 说明 |
|------|------|------|
| `groupAtOnly` | `true` | 群聊仅响应被 @ 的消息 |
| `privateAlways` | `true` | 私聊总是响应（总开关，需配合 `privateWhitelist` 使用） |
| `admins` | `[]` | 管理员列表（群聊中可用全部指令）。**只认主人 QQ 号 + 其他用户的 openid**——非主人的 QQ 号填了也匹配不上 |
| `owners` | `[]` | **机器人主人**：写操作（`/stocks` 的 `-add`/`-update`/`-del`）的唯一凭据，填 QQ 号。**空数组 = 谁都不能写**（fail-closed） |
| `privateWhitelist` | `[]` | 私聊白名单（名单外账号私聊一律拒绝；空数组 = 不限制） |
| `groupWhitelist` | `[]` | 群白名单（非空 = 仅响应列表内群；空数组 = 不限制） |
| `groupAdminOnly` | `false` | 群聊仅管理员可触发（非管理员消息一律不响应） |
| `groupRestrictedCmds` | `[]` | 群聊非管理员可用指令名白名单（如 `["ping","status","stocks"]`；空数组 = 不限制）。**注意**：`stocks` 放行只代表「能调这条指令」——查询 / `-list` 对所有人开放，`-add` / `-update` / `-del` 由代码内独立校验的 `owners` 名单决定（与 `admins` 无关） |
| `groupImages` | `false` | 群聊预览是否带图。**腾讯对群聊批量图片有安全审核**（批量图连发会被静默拦截、sendMsg 超时），默认 `false` = 群聊只发文本预览，图片自动**私聊补发**给触发者；`true` = 群聊直接带图 |
| `restrictedMsg` | 见文件 | 群聊非管理员使用受限指令时的提示 |
| `deniedMsg` | 见文件 | 私聊非白名单账号的拒绝提示；置 `""` 则完全忽略不回复 |
| `unknownMsg` | 见文件 | 未识别指令的提示 |
| `welcome` | 见文件 | 非指令消息的引导语；置 `""` 则不回复 |

> 指令名取 `routeCommand()` 返回的 `name`（不含 `/`）：`help` / `ping` / `status` / `echo` / `preview` / `news` / `ss` / `stock` / `stocks` / `zj` / `info` / `etfinfo`。别名（如 `/存活`、`/K线`、`/组合`）映射到同名 `name`，权限判断按 `name` 生效。
>
> **两层权限不要混淆**：`groupRestrictedCmds` / `admins` 只管「这条指令名能不能调」；`owners` 只管「组合能不能被写」。两者独立叠加——把 `stocks` 加进 `groupRestrictedCmds` 后，非管理员依然可以查询和 `-list`；而管理员即使能调 `stocks`，只要不在 `owners` 里，`-add` / `-update` / `-del` 照样被拒。

## 排障

- **改了指令没生效**：`index.js` 是 bind mount，但 Node 启动时载入内存，必须 `docker compose restart qq-reply`；改 `config.json` 则无需重启。
- **日志显示 WebSocket 一直重连**：`official-bot-gateway` 未启动或已重启。确认网关在跑（`docker compose ps`），日志里看到 `✅ WebSocket 已连接 ws://official-bot-gateway:3101` 即就绪。
- **@ 不识别**：确认 `BOT_UIN` 与网关转发的 `at` 标识一致（当前取 `${QQBOT_APP_ID}`）。可用 `/status` 查看机器人信息与通道状态。
- **私聊不响应**：检查 `privateAlways` 是否为 `false`，或你的 QQ 不在 `privateWhitelist` 内（收到 `deniedMsg` 说明被白名单拦截）。
- **群聊指令被拒**：普通成员仅可用 `groupRestrictedCmds` 内指令，属预期；如需放行，将该指令名加入 `groupRestrictedCmds`，或把账号加入 `admins`。
- **`/stocks -add/-update/-del` 报「仅限机器人主人」**：编辑命令只认 `owners` 名单，`admins` 不生效。确认 `reply/config.json` 的 `owners` 已填**你的 QQ 号**（非 openid），且容器改了配置后无需重启（每条消息热加载）。
- **主人能查询却不能写**：`owners` 里填成了 openid。`owners` 应填 QQ 号；网关 `bindings` 重置后代码会自动用网关下发的 `owner.openid` 兜底识别，但前提是网关侧主人身份正确。
- **群聊收不到图**：`groupImages: false` 时群聊只发文本、图片自动私聊补发给触发者，属预期。
- **图表「没字」**：容器内缺 `/app/fonts/cjk_sub.ttf`。在宿主执行 `bash ths-news/setup_fonts.sh` 补齐，bind mount 实时生效、无需重启。
- **`/stocks -add` 报「保存失败（服务端写盘异常）」**：`./reply/data` 没有正确挂载或不可写。确认 docker-compose 里 `./reply/data:/app/data`（**不能带 `:ro`**），且宿主 `reply/data/` 存在。
- **`/stocks -add` 报「未找到 / 无行情」**：标的解析走的是 `smartbox` 搜索 + 腾讯快照，确认代码或名称正确；港美股/ETF/商品同样支持保存。
- **`/stocks` 出图但某格是灰底「取数失败」**：该标的在该周期无数据（如港美股没有分钟 K、国际商品没有分钟 K），属预期，其余格子不受影响。
- **美股/港股分时突然全失败（`fetch failed` / `socket hang up`）**：东财 `push2his` / `push2` 会间歇性对调用方出口 IP 直接 RST（冷却数分钟不恢复、换 UA 无效，**不是限流**）。代码已内置节点轮换（`emFetchJson`：`push2his → push2 → push2delay`，成功即记忆），日志出现 `[em] 节点切换 xxx -> push2delay.eastmoney.com` 属正常降级；`push2delay` 的延时市场名单（8/10/128）不含沪深/美股/港股，取到的仍是实时数据。三个节点全挂时才真正不可用。
- **老 `portfolios.json` 想搬到新机器**：直接拷 `reply/data/portfolios.json`（gitignored）。格式见 `reply/data/portfolios.json.example`。

### 国际商品（`hf_` 前缀）的交易时段与横轴口径

| 品种 | 交易所 | 交易时段（北京时间） |
|---|---|---|
| 黄金 / 白银 / WTI / 天然气 / 美铜 | CME 系（COMEX / NYMEX） | **06:00 开盘 → 次日 05:00 收盘**，05:00–06:00 休 1 小时 |
| 布伦特原油 | ICE | **08:00 开盘 → 次日 07:00 收盘**，同样休 1 小时 |

> **不是 24 小时**（每天约 23 小时）；周六早晨收盘、周日早晨开盘。
>
> **分时图右端 ≠ 现在**：A股/港股/美股按**分钟**映射横轴（`tmin(t)/TOT`，午休体现为一段压缩区间），商品用**索引等距映射**（`mapX = X`）——所以休市时曲线照样铺满整幅图，右端只是「最后一个数据点」。是否实时，看标题的时段标注（`分时 09-10 06:00 至 09-11 01:33`）与横轴右端时刻。
>
> 会话内是 1 分钟一点、无缺口（实测 GC 1174 行 = 06:00→01:33 的 19h33m），因此索引等距与实际时间近似成正比，横轴首/中/末标签取的就是真实时刻。

## 已知修复

- **2026-09-11 · 分时均价线口径（科创板/北交所）**：腾讯 `minute/query` 的累计成交量单位并不统一——沪深主板 / 创业板 / 深市是**手**，科创板（688）/ 北交所等是**股**。原实现写死 `累计额 ÷ (累计量 × 100)`，导致科创板个股均价被缩小 100 倍（如 `688981` 算出均价 1.20 元、实际 119 元），Y 轴被拉到 `-3.58 ~ 125.28`，**价格线被压成一条直线**。现改为由 `buildAvgLine()` 用「末值与末价的偏离度」在 `÷100` / `÷1` 两档中自动择优；两档都对不上时宁可不画均价线，也不压扁价格线。影响 `/stock -t` 与 `/stocks -t` 两条渲染路径（canvas 与 SVG 兜底）。
- **2026-09-11 · 外盘商品分时横轴标签**（canvas 路径两处，SVG 路径本就正确）：
  1. **标签文字错乱**：新浪分时的 `t` 自带冒号（`06:00`），而 `fmtT()` 是给紧凑格式（`0930`）设计的，会拼成 `06::0`。现先去掉冒号再插入。
  2. **中间/末尾标签画到画布外**：canvas 用 `PAD + (tm / TOT) * plotW` 定位，但 `hf_` 的 `tm` 是**数据索引**（0..1173），`TOT = 240` 是 A股分钟数 → x 算成约 2077px（画布宽 1000）。现按 `isHF ? X(tm) : ...` 处理。
- **2026-09-11 · 外盘商品分时标题只写首行日期**：原来标题是 `分时 09-10`，但会话跨自然日、数据实际到 `09-11 01:33`，容易误读成「9-10 一整天」。现改为起止时段 `分时 09-10 06:00 至 09-11 01:33`（分隔用「至」，因为图表字体子集没有 `→` 字形）。
